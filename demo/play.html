pgen.zig Demo

Sample grammar:

tokens {
    "";  # Each instance of a quoted string automatically becomes one unique token
    number;  # A custom token
}
entry expression;  # Entry symbol

expression: term (("+" | "-") term)*;  # An expression is a term, possibly added/subtracted by other terms
term: factor (("*" | "/") factor)*;  # A term is a factor, possibly multiplied/divided by other factors
factor:
    number  # Most basic unit: number (a token)
    | "(" expression ")"  # An expression in parentheses is a single factor
    | "sin" "(" expression ")"  # We can add sin() function too
    | "sin" number  # We can allow omitting parentheses when a number follows too
    ;

You can also try to play with pgen.zig's own grammar for specifying grammar (the "meta grammar"); pgen.zig uses itself to generate its parser!:

tokens {
    WORD;
    STRING;
    "";
    ""k;
}

entry grammar;

grammar:
    "tokens"k "{"
        token_decl+
    "}"
    "entry"k WORD ";"
    production+;
# String must be empty in token_decl but no way to enforce that
token_decl: (WORD | STRING) ";";
production: nonterminal_qualifier WORD ":" rhs ";";
nonterminal_qualifier: ["nodeless"k];

rhs_atom:
    WORD  # Non-terminal/terminal
    | STRING  # Terminal, must be nonempty but no way to enforce that
    | "(" rhs ")"
    | "[" rhs "]";  # Optional
# Stacking * and + (e.g. "*+") never makes sense
rhs_term: rhs_atom ["*" | "+"];
rhs_factor:
    rhs_term+
    | "epsilon"k;
rhs: rhs_factor ("|" rhs_factor)*;

Try to mess around with the grammar and see how the program detects a problem in the grammar (e.g. undeclared name).
